# hxyfront-62013 木结构榫卯构件测绘

源提示词编号：8

古建筑木结构榫卯构件测绘前端项目，内置**修缮版本闭环**：测绘人员录入建筑名称、构件编号、木材种类、榫卯类型、截面尺寸、病害位置、变形情况，系统按规则自动生成修缮建议。页面包含构件清单、榫卯类型筛选、尺寸记录、病害标记图、单栋建筑的构件关系视图与施工清单。

## 修缮版本闭环规则

1. **构件编号唯一**：构件身份 =（建筑，构件编号）。同一建筑内重复提交同一编号即“重新测绘”，版本号递增，不产生第二个构件。
2. **录入齐全性**：木材、榫卯类型、截面尺寸、病害位置、变形必须齐全（无病害/无变形时以空记录显式明示）。
3. **拒绝不覆盖**：截面尺寸非正、病害位置越界（轴向超出 [0, 构件长]，横向超出 [0, 截面宽]）等非法录入一律拒绝，**不改动任何既有测绘与建议**。
4. **建议闭环**：修缮建议只由最新有效测绘生成；重新测绘提交成功的那一刻，旧版本置为“已被取代”、旧建议立即失效，历史版本与历史建议永久可查。
5. **同批视图**：构件关系视图按测绘批次构建，只引用各构件“同批次且有效”的版本；本批未测或本批版本已被取代的构件进入排除清单并注明原因。施工清单完全由该视图派生，过期版本无法混入。

## 目录结构

```
src/domain/    领域核心（无 UI 依赖，可独立测试）
  types.ts       模型：测绘版本、修缮建议、关系视图、施工清单
  validate.ts    录入校验（齐全性 / 截面非正 / 病害越界）
  suggest.ts     规则化修缮建议生成
  store.ts       SurveyStore：版本更替、建议失效、同批视图、施工清单
  seed.ts        演示数据（春测 3 件 + 秋测重测，直观呈现闭环）
  store.test.ts  闭环规则测试（vitest，10 例）
src/ui/        录入表单 / 构件清单（病害标记图+版本历史）/ 关系视图+施工清单
```
